# date-utils

## Требования
- maven 3.9.11 или выше
- java 25 или выше

## Задача
Необходимо парсить дату и время с микросекундами, после чего преобразовать в формат yyyyMMddHHmmss

### Тестовые данные
- 2026-11-20T10:04:05Z
- 2026-11-20T10:04:05.906Z
- 2026-11-20T10:04:05.991178Z

### Что важно знать
ITU.parserDateTime требует полный timestamp с офсетом и возвращает OffsetDateTime - как раз то, что нужно для конвертации в zoneId через atZoneSameInstant.
Бонус, которого нет у стандартного Instant.parse:
- библиотека честно работает с високосными секундами (секунда 60) - при парсинге такой строки прилетит LeapSecondException, и у исключения есть хелперы, чтобы решить, что с ним делать. Если входные данные из внешних систем, это может оказаться неожиданно полезным.
- нюанс библиотеки: офсет -00:00 она запрещает (по RFC-3339 это "офсет неизвестен", а не UTC) - бросит ошибку.

LocalDAteTime.parse с литералом 'Z' игнорировал данную зону, а ITU.parserDateTime парсит офсет по-настоящему.
Если однажды придёт строка с -05:00, результат будет корректным моментом времени, переведённым в нужную зона, а не "как повезло".
